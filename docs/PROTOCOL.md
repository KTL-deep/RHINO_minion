# Bridge protocol 0.1

RHINO Minion использует версионированные JSON-сообщения поверх локального WebSocket. На этапе 1 транспорт будет доступен только через loopback.

## Envelope

Каждый запрос содержит:

- `protocol_version` — версия wire protocol;
- `request_id` — UUID идемпотентности и трассировки;
- `session_id` — UUID запущенной сессии Rhino;
- `type` — тип сообщения;
- `payload` — данные сообщения.

Поддерживаемые типы версии 0.1: `handshake`, `get_scene`, `execute_batch`.

## Совместимость

Несовпадение major/minor версии в V0 завершается ошибкой `PROTOCOL_ERROR`. Неизвестные поля отклоняются. Новая версия схемы добавляется отдельным файлом и не изменяет семантику существующей версии.

## Идемпотентность

Bridge хранит ограниченный кэш обработанных `request_id`. Повторный запрос возвращает исходный результат и не должен повторно создавать геометрию.

## Batch

`execute_batch` содержит до 50 последовательных операций. Весь batch получает одну Undo-запись. Политика отката при ошибке будет реализована и проверена на этапе 1.

Канонические JSON Schema находятся в `schemas/`, примеры — в `examples/requests/`.
