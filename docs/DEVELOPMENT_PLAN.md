# План разработки RHINO Minion

## 1. Цель продукта

RHINO Minion — ассистент для Rhino 8, который преобразует текстовый запрос пользователя в контролируемый набор операций RhinoCommon и создаёт редактируемую геометрию непосредственно в открытом документе Rhino.

Базовый пользовательский цикл:

1. Пользователь вводит запрос в панели Rhino.
2. AI анализирует запрос и текущее состояние сцены.
3. AI формирует параметрическое описание объекта и план операций.
4. Локальный bridge проверяет операции и выполняет их через RhinoCommon.
5. Пользователь видит результат, при необходимости отменяет его через Undo или вводит следующую правку.

Первая версия предназначена для архитектурного massing. BIM, точная реконструкция чертежей, генерация Grasshopper-графов и облачные вычисления не входят в MVP.

## 2. Принципы

- LLM не создаёт и не изменяет `.3dm` напрямую.
- LLM не исполняет произвольный Python или C# код.
- Все изменения выполняются через небольшой типизированный набор инструментов.
- Аргументы инструментов валидируются до изменения документа.
- Одна пользовательская команда соответствует одной транзакции Rhino Undo.
- Все изменения RhinoDoc выполняются в UI-потоке Rhino.
- Rhino GUID является основным идентификатором существующего объекта.
- Все размеры передаются явно; единицы документа всегда включаются в контекст.
- Результат должен оставаться редактируемой Rhino-геометрией.
- Ошибки отдельных операций должны быть структурированными и понятными агенту.

## 3. Границы MVP (V0)

### Пользовательские сценарии

- Получить краткое описание открытой сцены и выделенных объектов.
- Создать box по размерам и положению.
- Создать polyline по набору точек.
- Выдавить замкнутую плоскую кривую.
- Переместить, повернуть или масштабировать существующие объекты.
- Выполнить несколько операций как одну AI-команду.
- Отменить всю AI-команду стандартным `Ctrl+Z`.

Пример целевого запроса:

> Создай башню 30 × 20 м высотой 80 м со ступенчатой верхушкой.

### Инструменты V0

| Инструмент | Назначение |
|---|---|
| `get_scene` | Единицы, объекты, слои, bounding boxes и выделение |
| `create_box` | Создание прямоугольного объёма |
| `create_polyline` | Создание открытой или замкнутой ломаной |
| `extrude` | Выдавливание плоской кривой |
| `transform` | Move, rotate и scale |

### Не входит в V0

- Загрузка референсных изображений.
- Распознавание планов и фасадов.
- Boolean, loft, sweep и сложные поверхности.
- Grasshopper.
- Rhino Compute.
- Revit, IFC и Blender.
- Совместная работа нескольких пользователей.
- Автономное выполнение длинных цепочек без лимитов и подтверждения.

## 4. Целевая архитектура

```text
Rhino 8
└── RHINO Minion plugin (.NET / RhinoCommon / Eto)
    ├── Chat panel
    ├── Scene reader
    ├── Tool registry
    ├── Schema validator
    ├── Command executor
    ├── Undo transaction manager
    └── localhost WebSocket client/server
                  ↕ JSON messages
Python backend (FastAPI / Pydantic)
├── Session manager
├── Prompt and context builder
├── Planner
├── Tool-call executor loop
├── LLM provider adapter
└── Audit log

Cloud control plane (production)
├── User authentication / sessions
├── Billing and subscriptions
├── Entitlements and usage ledger
├── AI generation gateway
├── Rate limits and abuse controls
└── Server-side provider secrets
```

Для первого вертикального прототипа UI и LLM могут быть заменены консольным тестовым клиентом. Это позволит проверить Rhino bridge независимо от модели и интерфейса.

## 5. Компоненты

### 5.1 Rhino plugin

Ответственность:

- регистрация плагина и команды открытия панели;
- подключение только к loopback-интерфейсу;
- чтение RhinoDoc и selection;
- преобразование валидированных DTO в вызовы RhinoCommon;
- выполнение мутаций через `RhinoApp.InvokeOnUiThread()`;
- группировка пакетной команды через `BeginUndoRecord()` / `EndUndoRecord()`;
- перерисовка viewport;
- возврат GUID созданных и изменённых объектов;
- преобразование исключений в структурированные ошибки.

### 5.2 Backend

Ответственность:

- управление диалоговыми сессиями;
- формирование компактного scene context;
- запрос к LLM с доступными JSON-инструментами;
- ограниченный tool-calling loop;
- проверка входных и выходных DTO через Pydantic;
- тайм-ауты, лимиты операций и журналирование;
- независимый адаптер провайдера модели.

### 5.3 AI orchestration

Логические стадии:

```text
Текст пользователя
→ нормализованный architectural intent
→ geometry plan
→ валидированные tool calls
→ результат Rhino
→ краткий ответ пользователю
```

Planner не должен выдумывать GUID, единицы или результаты геометрических операций. При неоднозначной ссылке на объект он использует selection, уникальное имя или запрашивает уточнение.

### 5.4 UI

Минимальная Eto-панель:

- история сообщений;
- поле ввода;
- кнопка отправки/остановки;
- индикатор подключения;
- отображение выполняемых операций;
- понятная ошибка с возможностью повторить запрос.

## 6. Протокол bridge

Транспорт V0: WebSocket на `127.0.0.1`. Соединение не должно слушать внешние сетевые интерфейсы.

### Запрос

```json
{
  "protocol_version": "0.1",
  "request_id": "uuid",
  "session_id": "uuid",
  "type": "execute_batch",
  "payload": {
    "label": "AI: create stepped tower",
    "operations": [
      {
        "operation_id": "op-1",
        "tool": "create_box",
        "arguments": {
          "origin": [0, 0, 0],
          "width": 30000,
          "depth": 20000,
          "height": 60000,
          "layer": "AI::Massing",
          "name": "Tower_Base"
        }
      }
    ]
  }
}
```

### Успешный ответ

```json
{
  "request_id": "uuid",
  "ok": true,
  "result": {
    "operations": [
      {
        "operation_id": "op-1",
        "object_ids": ["rhino-guid"]
      }
    ]
  }
}
```

### Ошибка

```json
{
  "request_id": "uuid",
  "ok": false,
  "error": {
    "code": "INVALID_ARGUMENT",
    "message": "height must be greater than zero",
    "operation_id": "op-1",
    "details": {}
  }
}
```

Обязательные категории ошибок: `INVALID_ARGUMENT`, `OBJECT_NOT_FOUND`, `GEOMETRY_FAILED`, `DOCUMENT_UNAVAILABLE`, `TIMEOUT`, `PROTOCOL_ERROR` и `INTERNAL_ERROR`.

## 7. Scene graph V0

`get_scene` возвращает компактные метаданные, а не сериализованную геометрию:

```json
{
  "document_id": "runtime-id",
  "units": "millimeters",
  "absolute_tolerance": 0.01,
  "angle_tolerance_degrees": 1.0,
  "objects": [
    {
      "id": "rhino-guid",
      "name": "Tower_Massing",
      "type": "Brep",
      "layer": "AI::Massing",
      "selected": true,
      "bbox": {
        "min": [-14000, -10000, 0],
        "max": [14000, 10000, 80000]
      }
    }
  ]
}
```

Для больших документов вводятся фильтры, лимит числа объектов и признак усечения результата.

## 8. Безопасность и надёжность

- Принимать соединения только с `127.0.0.1`/`::1`.
- Использовать случайный session secret при запуске плагина.
- Не поддерживать операции выполнения кода, shell-команд и загрузки сборок.
- Ограничить размер сообщения, число операций в batch и время выполнения.
- Проверять конечность чисел (`NaN` и infinity запрещены), диапазоны и существование GUID.
- Запрещать удаление и замену объектов вне явно переданного набора GUID.
- При ошибке batch откатывать всю команду, если это технически возможно; иначе возвращать фактически применённые операции.
- Не передавать содержимое документа облачной модели без явной необходимости.
- Не хранить API-ключи в репозитории; использовать переменные окружения или системное хранилище секретов.
- Не журналировать секреты, токены и полные пользовательские промпты без настройки согласия.

## 9. Этапы разработки

### Этап 0 — каркас репозитория

Результат:

- solution для C#-плагина;
- Python package для backend;
- общая спецификация протокола;
- команды сборки, запуска и тестирования;
- `.gitignore`, конфигурация форматирования и базовый CI.

Критерий готовности: чистый checkout собирается по документированной инструкции.

### Этап 1 — Rhino bridge без AI

Результат:

- загрузка плагина в Rhino 8;
- WebSocket-соединение с тестовым клиентом;
- реализация пяти инструментов V0;
- GUID в ответах;
- UI-thread dispatch и Undo transaction;
- структурированные ошибки.

Критерий готовности: тестовый JSON-запрос создаёт ступенчатую башню, а один `Ctrl+Z` удаляет весь результат batch.

### Этап 2 — scene context и редактирование

Результат:

- `get_scene` с selection и bounding boxes;
- фильтрация по GUID, layer, type и selection;
- операции над ранее созданными объектами;
- проверка поведения при удалённых или устаревших GUID.

Критерий готовности: после создания объекта запрос «сделай выделенное на 20% уже» корректно изменяет выбранную геометрию.

### Этап 3 — LLM backend

Результат:

- provider-independent LLM adapter;
- system prompt и схемы инструментов;
- Planner → Executor pipeline;
- tool loop с лимитами и тайм-аутами;
- сохранение связей между логическими сущностями и Rhino GUID;
- mock-модель для автоматических тестов.

Критерий готовности: набор эталонных текстовых запросов стабильно превращается в валидные tool calls без произвольного кода.

### Этап 4 — встроенная панель

Результат:

- Eto chat panel;
- управление сессией и подключением;
- визуальный статус операций;
- отмена текущего запроса;
- понятные сообщения об ошибках.

Критерий готовности: весь основной сценарий выполняется внутри Rhino без консольного клиента.

### Этап 5 — стабилизация V0

Результат:

- интеграционные тесты в Rhino;
- тестирование документов с разными единицами и tolerance;
- лимиты, телеметрия без чувствительных данных и диагностические логи;
- установочный пакет;
- документация пользователя и разработчика.

Критерий готовности: пилотный пользователь может установить продукт и выполнить основные сценарии без участия разработчика.

### Этап 6 — авторизация, подписки и коммерческий gateway

Результат:

- аккаунт RHINO Minion через стандартный OIDC/OAuth-провайдер;
- безопасный вход desktop/frontend через Authorization Code + PKCE;
- короткоживущий access token и ротация refresh token;
- облачный entitlement service для планов Free/Trial/Pro и credit packs;
- hosted checkout и customer portal платёжного провайдера;
- отдельный web-сайт для входа, покупки и управления подпиской; desktop остаётся интерфейсом чата и при отсутствии entitlement перенаправляет пользователя на сайт;
- webhook-обработка оплаты с проверкой подписи и идемпотентностью;
- usage ledger, квоты, rate limits и защита от параллельного перерасхода;
- AI gateway, который хранит OpenAI API key только на сервере;
- опциональный BYOK-режим с зашифрованным пользовательским API key;
- удалённый logout/revoke и минимальный audit trail.

Критерий готовности: пользователь входит в RHINO Minion, покупает план или пакет кредитов, entitlement обновляется через подписанный webhook, а генерация выполняется без передачи provider key во frontend, Rhino plugin или локальные логи.

## 10. Последующие версии

Полный перечень категорий Rhino и их текущий статус ведётся в
[`RHINO_CAPABILITY_MATRIX.md`](RHINO_CAPABILITY_MATRIX.md). Приоритет до подключения
свободного AI — расширить типизированный Rhino tool layer и runtime discovery возможностей.

### V1 — AI editing

- delete, duplicate, group и layer tools;
- расширенные transform и arrays;
- circle, rectangle, offset, loft, sweep и booleans;
- устойчивые ссылки на сущности и история их происхождения;
- viewport capture как дополнительный контекст;
- предварительный просмотр потенциально разрушительных операций.

### V2 — Reference image to massing

- загрузка изображения;
- multimodal-анализ композиции;
- масштаб по заданной высоте или известному размеру;
- параметрическая приблизительная реконструкция масс;
- отображение предположений и неопределённости.

### V3 — Architecture agent

- architectural geometry DSL;
- уровни, плиты, ядра, подиумы и фасадные системы;
- генерация редактируемых Grasshopper definitions;
- площади и простые ограничения программы;
- генерация и ранжирование вариантов через Rhino Compute;
- экспорт DSL в другие CAD/BIM-системы.

## 11. Architectural Geometry DSL

DSL вводится после работоспособного V0, но границы инструментов сразу проектируются с учётом будущего промежуточного представления.

Пример:

```yaml
schema_version: "0.1"
building:
  id: tower-a
  type: residential_tower
  footprint:
    type: rectangle
    width: 28000
    depth: 20000
  levels:
    count: 12
    floor_to_floor: 3200
  massing:
    twist:
      total_degrees: 18
    taper:
      bottom_scale: 1.0
      top_scale: 0.75
```

DSL должен быть версионируемым, детерминированно компилироваться в операции и не содержать исполняемого пользовательского кода.

## 12. Тестовая стратегия

### Unit tests

- сериализация и валидация DTO;
- матрицы transform;
- преобразование единиц;
- построение geometry plan;
- коды и формат ошибок;
- лимиты tool loop.

### Contract tests

- одинаковые JSON fixtures для C# и Python;
- совместимость версий протокола;
- неизвестные поля и инструменты;
- частичные, повторные и просроченные запросы.

### Rhino integration tests

- создание валидной геометрии;
- ожидаемые размеры bounding box;
- корректные GUID, имена и слои;
- выполнение только в активном документе;
- один Undo step на batch;
- отсутствие частичного результата после ошибки.

### AI evaluation set

Поддерживать версионируемый набор запросов:

- однозначное создание объекта;
- последовательная правка через selection;
- ссылки «он», «это», «выбранное»;
- разные единицы измерения;
- невозможная или неоднозначная операция;
- попытка заставить модель выполнить произвольный код;
- запрос за пределами доступных возможностей.

## 13. Нефункциональные требования V0

- Ответ `get_scene` для обычного документа: целевое время до 500 мс.
- Начало простой геометрической операции: целевое время до 250 мс без учёта LLM.
- Bridge не блокирует UI во время сетевого ожидания.
- Каждая операция имеет `request_id`, `session_id` и диагностический correlation ID.
- Повторная отправка одного request ID не должна случайно дублировать геометрию.
- Протокол и DSL имеют явные номера версий.
- Поддерживаемая платформа V0: все сервис-релизы Rhino 8 for Windows, начиная с Rhino 8.0; macOS рассматривается после стабилизации.

## 15. Definition of Done для V0

V0 считается завершённой, когда:

- плагин устанавливается и загружается в Rhino 8;
- backend автоматически соединяется с конкретной сессией плагина;
- все пять инструментов доступны через версионированный протокол;
- агент получает единицы, selection и компактную сцену;
- эталонный запрос создаёт корректную ступенчатую башню;
- последующая команда изменяет созданный объект по его GUID;
- каждая команда отменяется одним `Ctrl+Z`;
- невалидные запросы не оставляют частично созданную геометрию;
- LLM не имеет пути к выполнению произвольного локального кода;
- unit, contract и согласованный набор integration tests проходят;
- установка, настройка API-ключа, запуск и диагностика документированы.

## 17. Решения, которые нужно зафиксировать до реализации

- Матрица smoke-тестов для Rhino 8.0, пользовательской Rhino 8.16 и последнего стабильного Rhino 8 SR.
- Кто открывает WebSocket server: Rhino plugin или backend.
- Модель аутентификации localhost-сессии и передача session secret.
- Политика atomic rollback для batch при ошибке RhinoCommon.
- Первый поддерживаемый LLM provider и формат конфигурации ключа.
- Лицензия проекта и стратегия распространения плагина.
- Нужна ли работа полностью локально или допустима передача scene metadata облачной модели.
- Провайдер identity/OIDC, платёжный провайдер, юридическое лицо и поддерживаемые страны продаж.
- Тарифы RHINO Minion, единица внутреннего кредита, лимиты и политика возвратов.
- Разрешён ли BYOK и где хранится зашифрованный пользовательский provider key.

Эти решения не блокируют создание структуры и протокольных DTO, но должны быть приняты до завершения Rhino bridge и подключения реального LLM.
